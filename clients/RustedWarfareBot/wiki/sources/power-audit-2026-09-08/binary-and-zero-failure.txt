== zero-failure claims: exact upper bounds, 1 - alpha^(1/n) at alpha=0.05 ==
n=  48: true rate excluded above 0.0605  (any single "0/48 wins both arms" panel)
n= 120: true rate excluded above 0.0247  (flame-nocover post-certification "0/~120")
n= 312: true rate excluded above 0.0096  (Hard rung 307/312: bound on the win rate SHORTFALL uses failures, not this row)

sd=0 caution, per the umbrella correction: feeding a zero-variance identity read
into t_crit*sd/sqrt(n) returns MDE 0 and reads as infinite power. rusted's
byte-identity claims (evolve1/evolve2 graduate identity, identcert's policy-column
and spend-table identity) rest on construction and the pinned campaign e2e, not on
a t; any statistical reading of "k runs identical" is bounded by 1 - alpha^(1/k).

Method note, recorded because the audit holds itself to its own standard: the first
pass at the smallest-rejecting-split search iterated k DESCENDING and returned the
trivial d:0 split (reported nowhere; caught before publication). The ascending
search above is the correct form, and it is exactly the class of arithmetic the
shared helper should own with a test that watches it fail first.
